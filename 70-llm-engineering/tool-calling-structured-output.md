# Tool calling, structured output, агентные пайплайны

> **Зачем на собесе:** второй после RAG блок для AI-позиций (Магнит, 1440). Проверяют: умеешь ли встроить LLM в бэкенд надёжно — с типизированным выводом, инструментами, обработкой ошибок, а не «отправил промпт, распарсил текст».

## Минимум для собеса

- **Structured output:** модель возвращает JSON по схеме (Pydantic-модель → JSON Schema → `response_format`/tool schema). Валидация Pydantic на выходе, ретрай с сообщением об ошибке валидации, ограничение числа ретраев. Никогда не парсить свободный текст регулярками, если есть structured mode. Библиотеки: нативные SDK (Anthropic/OpenAI), `instructor`, `pydantic-ai`.
- **Tool calling (function calling):** описываешь функции (имя, описание, JSON-схема аргументов) → модель решает вызвать → твой код исполняет → результат обратно в контекст → модель продолжает. Цикл до финального ответа. Инструменты — обычный код: валидация аргументов, таймауты, права, идемпотентность для side-effect-инструментов, лимит итераций.
- **Агент = LLM + инструменты + цикл + память.** Паттерны по возрастанию сложности: один вызов с structured output → цепочка (prompt chaining) → роутинг → параллелизация → orchestrator-workers → автономный агент. Правило: самая простая схема, которая решает задачу; агентность добавляет стоимость, латентность и непредсказуемость.
- **Надёжность:** таймауты на вызовы модели, ретраи на 429/5xx с backoff, фолбэк на другую модель/провайдера, circuit breaker ([[resilience-patterns]]); идемпотентность при повторной обработке; лимит токенов/итераций/стоимости на запрос; graceful degradation (ответ без инструмента).
- **Контекст:** system prompt с ролью и правилами, few-shot примеры, управление длиной (summarization, окно), prompt caching для длинных статичных префиксов (экономия).
- **Безопасность:** prompt injection (через документы/инструменты/пользовательский ввод) → инструменты с минимальными правами, подтверждение опасных действий, изоляция, валидация выходов; PII и секреты не в промпт; логирование запросов/ответов с маскированием.
- **Стриминг** ответов (SSE) для UX; async-клиенты в FastAPI; очереди для долгих агентных задач ([[task-queues]]).
- **MCP** (Model Context Protocol) — стандарт подключения инструментов/данных к моделям; знать, что это.
- **Версионирование промптов** как кода (в репозитории, с тестами/evals), не в админке «на горячую».

## Вопросы с собесов

- [ ] Как получаешь от модели структурированный ответ и что делаешь при невалидном? → *схема, Pydantic, ретрай с ошибкой, лимит*
- [ ] Как работает tool calling? Нарисуй цикл. → *схемы → решение → исполнение → результат → продолжение*
- [ ] Чем агент отличается от цепочки промптов? Когда агент не нужен? → *цикл с решениями модели; почти всегда хватает workflow*
- [ ] Модель-провайдер отвечает 429/таймаутами. Что делает сервис? → *backoff, фолбэк, breaker, деградация*
- [ ] Что такое prompt injection и как защищаешь инструменты? → *минимальные права, валидация, подтверждения*
- [ ] Как тестируешь код с LLM-вызовами? → *фейки/записи в unit; evals отдельно ([[evals-cost-latency]])*
- [ ] Как ограничиваешь стоимость одного запроса агента? → *max tokens, max iterations, бюджет, кэш*
- [ ] Промпты где хранишь и как меняешь? → *в коде, версии, evals перед выкаткой*
