# Работа с AI-агентами и ревью сгенерированного кода

> **Зачем на собесе:** уровень 1 по анализу вакансий: Циан прямо спрашивает на собесе, банк выдаёт Claude Code, Constructor ожидает по умолчанию. Это не отдельный навык, а способ работы, и сеньорная часть — в ревью, постановке задач и понимании, где агенту нельзя доверять. Если есть реальный опыт — его надо уметь рассказать.

## Минимум для собеса

- **Что использую и как:** Claude Code / Cursor / Copilot — для чего именно: генерация шаблонного кода, тесты, миграции, рефакторинг, объяснение незнакомого кода, черновики документации, разбор логов. Назвать конкретные инструменты и конкретные задачи из практики.
- **Постановка задачи агенту:** контекст (структура проекта, конвенции, CLAUDE.md/правила), чёткие критерии готовности, маленькие шаги, требование запускать тесты/линтер, план перед кодом для нетривиального. Плохой промпт = плохой код.
- **Где агенту нельзя доверять:** безопасность (инъекции, секреты, права), конкурентность и транзакции, граничные случаи, миграции на проде, выдуманные API/параметры библиотек (проверять по докам), производительность (N+1, лишние запросы), «уверенное» переписывание того, о чём не просили, устаревшие версии библиотек.
- **Ревью сгенерированного кода** — как любого другого, но с поправкой на типичные ошибки: избыточность и дублирование, тесты, которые проверяют мок, а не поведение, игнорирование конвенций проекта, незаметное изменение логики при рефакторинге. Чеклист — [code-review-exercise](../90-live-coding/code-review-exercise.md).
- **Ответственность** за код — у инженера, не у модели. Понимать каждую строку, которую коммитишь.
- **Процессы в команде:** правила использования (что можно отправлять в модель, секреты и PII, лицензии), AI-ревью PR как дополнительный, а не единственный слой; измерять эффект (lead time, дефекты), а не «ощущения».
- **Эффект честно:** где ускоряет (boilerplate, тесты, незнакомые области) и где нет (сложная доменная логика, архитектурные решения, отладка гонок).
- **Свой кейс:** любая задача, где модель делала работу за людей (разбор документов, классификация, извлечение данных) — пайплайн, контроль качества, стоимость, где модель ошибалась ([stories](../00-strategy/stories.md), история 2).

## Вопросы с собесов

- [ ] Какие AI-инструменты используешь и для каких задач? → *конкретно, с примерами*
- [ ] Как ревьюишь сгенерированный код? Чем он отличается от человеческого? → *типовые ошибки; чеклист*
- [ ] Где не доверяешь агенту? → *безопасность, конкурентность, миграции, выдуманные API*
- [ ] Как ставишь задачу агенту, чтобы получить хороший результат? → *контекст, критерии, шаги, тесты*
- [ ] Был ли случай, когда AI-инструмент навредил? Что изменил после? → *честный пример*
- [ ] Какие правила использования AI предложил бы команде? → *данные, ревью, ответственность, измерение*
- [ ] Как AI меняет роль сеньора? → *больше ревью, постановки, архитектуры; меньше набора кода*

## Углубление

- Agentic workflows: планирование → реализация → проверка, субагенты, MCP-инструменты, контекстные файлы в репозитории.
- Генерация тестов и property-based тестов агентом; агент как «второй ревьюер» в CI.
- Безопасность: prompt injection через содержимое репозитория/тикетов, утечка секретов в контекст.
- Измерение эффекта: эксперименты, DORA-метрики.
