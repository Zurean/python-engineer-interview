# Миграции схемы без даунтайма

> **Зачем на собесе:** Senior-вопрос «как переименовать колонку на живой базе». Короткая тема, но ответ сразу показывает, был ли опыт эксплуатации. Учится за вечер.

## Минимум для собеса

- **Принцип expand → migrate → contract:** схема должна быть совместима и со старым, и с новым кодом одновременно, потому что во время деплоя работают обе версии.
- **Переименование колонки:** 1) добавить новую колонку; 2) код пишет в обе, читает из старой (или новой с фолбэком); 3) бэкфилл батчами; 4) код читает из новой; 5) перестать писать в старую; 6) удалить старую. Альтернатива для чтения — view или generated column. Никогда — `ALTER TABLE RENAME` одним шагом под нагрузкой с живым старым кодом.
- **Добавление NOT NULL колонки:** добавить nullable → бэкфилл → `ADD CONSTRAINT ... CHECK (col IS NOT NULL) NOT VALID` → `VALIDATE CONSTRAINT` (не блокирует) → `SET NOT NULL` (с 12-й использует существующий check). 
- **Индексы:** `CREATE INDEX CONCURRENTLY` (не в транзакции; в Alembic — `op.execute` с `autocommit`/`transaction_per_migration`). При ошибке остаётся invalid-индекс — дропнуть и повторить.
- **Внешние ключи и check:** `NOT VALID` + `VALIDATE` отдельно.
- **DEFAULT:** с Postgres 11 `ADD COLUMN ... DEFAULT const` без rewrite; volatile default (например, `now()`) — rewrite.
- **Удаление колонки:** сначала убрать из кода/моделей (SQLAlchemy не должен её `SELECT`-ить), потом `DROP`. Drop — быстрый, но тоже `ACCESS EXCLUSIVE`.
- **Всегда `lock_timeout`** (например, 2–5 с) и ретрай миграции: DDL в очереди за долгой транзакцией блокирует всех новых читателей.
- **Бэкфилл большими батчами** по PK с паузами, не одним `UPDATE` на всю таблицу (блокировки, WAL, bloat, репликационный лаг).
- **Изменение типа колонки** = rewrite + lock → через новую колонку.
- Миграции отделять от деплоя кода: сначала миграция (совместимая), потом код; откат кода не должен требовать отката схемы.

## Вопросы с собесов

- [ ] Как безопасно переименовать колонку на живой базе без даунтайма? → *expand/contract, двойная запись, бэкфилл*
- [ ] Как добавить NOT NULL колонку в таблицу на 100 млн строк? → *nullable → бэкфилл → NOT VALID check → validate → set not null*
- [ ] Почему `CREATE INDEX` может положить прод и как делать правильно? → *блокирует запись; CONCURRENTLY*
- [ ] Что такое `lock_timeout` и зачем он в миграциях? → *не стоять в очереди за долгой транзакцией*
- [ ] Миграция выполняется 2 часа. Как перестроить? → *батчи, отделить бэкфилл от DDL*
- [ ] Как откатывать миграции? Пишешь downgrade? → *только совместимые изменения; откат кода без отката схемы*

## Углубление

- Инструменты и чеклисты: `strong_migrations` (идеи переносимы), `squawk` — линтер миграций.
- Logical replication / pg_online_schema_change-подходы для тяжёлых перестроений.
- Миграции в многорегиональной/шардированной БД.
- Blue/green для БД и почему это почти никогда не делается.
