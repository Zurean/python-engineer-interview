# Векторные БД глубже pgvector

> **Зачем на собесе:** AI-позиции при масштабе; 1 из 7 явно. Для старта достаточно pgvector (см. [[rag]]). Здесь — что знать, чтобы обосновать выбор.

## Минимум (стаб)

- Индексы ANN: HNSW (граф, быстрый поиск, память), IVF (кластеры, дешевле память, нужен `nprobe`), квантование (PQ/SQ). Параметры и трейдофф recall vs latency vs память.
- pgvector: `vector` тип, `<=>` cosine, HNSW/IVFFlat индексы, лимиты (размерность, объём до единиц миллионов векторов комфортно), фильтрация по метаданным через обычный WHERE (плюс: одна БД, транзакции).
- Отдельные: Qdrant (Rust, фильтры, payload, gRPC, лёгкий self-host), Weaviate, Milvus, Elasticsearch/OpenSearch kNN (если уже есть), managed (Pinecone). Когда переходить: десятки миллионов векторов, строгие требования к латентности, сложные фильтры, отдельное масштабирование.
- Гибридный поиск (вектор + BM25), multi-tenancy, обновления/удаления, бэкапы.

## Вопросы с собесов

- [ ] pgvector vs Qdrant — когда переходить? → *масштаб, фильтры, латентность, операционная сложность*
- [ ] HNSW vs IVF? → *скорость/память vs дешевле/настройка*
