# Кейсы для тренировки (вслух, с таймером)

> **Зачем на собесе:** секция — это навык, а не знание. 6 кейсов ниже покрывают типовые вопросы российских собесов. На каждый — 45 минут по [[sd-framework]], потом сверка с подсказками.

## Как тренировать

1. Таймер 45 минут. Говорить вслух, рисовать (бумага/excalidraw).
2. После — открыть подсказки и отметить, что упустил.
3. Через неделю — повторить тот же кейс. Второй проход обычно вдвое лучше.
4. Записывать в «Мои заметки» свои слабые места (например, «забываю про failure modes»).

## Кейсы

### 1. Сокращатель ссылок (разминочный)
- [ ] Прошёл
- Подсказки: генерация ключа (base62 от счётчика / hash / предгенерированный пул), redirect 301 vs 302 (аналитика), чтение >> запись → кэш, статистика кликов через очередь, TTL/удаление, абуз и rate limit.

### 2. Сервис уведомлений (push/email/SMS)
- [ ] Прошёл
- Подсказки: API приёма → очередь → воркеры по каналам, приоритеты, ретраи с backoff, идемпотентность (не слать дважды), DLQ, шаблоны, rate limits провайдеров, статусы доставки, батчинг, расписание/отложенные.

### 3. Лента новостей / таймлайн (fan-out)
- [ ] Прошёл
- Подсказки: fan-out on write (предрасчёт ленты в Redis) vs on read (собрать при запросе), гибрид для «знаменитостей», пагинация курсором, кэш, ранжирование как отдельный сервис, eventual consistency.

### 4. Платёжный/биллинговый сервис (банковский кейс)
- [ ] Прошёл
- Подсказки: идемпотентность на всех операциях (Idempotency-Key), транзакции и балансы (атомарный UPDATE с условием, double-entry ledger), состояния платежа (state machine), outbox для событий, взаимодействие с внешним провайдером (таймауты, ретраи, реконсиляция), аудит, PCI-соображения (не хранить карты), строгая консистентность.

### 5. Обработка документов / RAG-сервис (см. capstone)
- [ ] Прошёл
- Подсказки: загрузка в S3 через presigned URL → событие → пайплайн (парсинг, чанкинг, эмбеддинги) через Kafka с ретраями → pgvector/Qdrant; API запроса: retrieval → rerank → LLM; кэш ответов; стоимость и латентность; evals; multi-tenancy и доступы; мониторинг качества. Связь: [[rag]], [[rag-service-project]].

### 6. Rate limiter / API gateway
- [ ] Прошёл
- Подсказки: алгоритмы (token bucket, sliding window log/counter), хранение в Redis с атомарными Lua-скриптами, распределённость и гонки, ключи (user/IP/API key), ответ 429 + Retry-After, деградация при недоступности Redis (fail-open vs fail-closed).

### Дополнительно (если время есть)
- Чат / мессенджер (WebSocket, доставка, порядок, оффлайн).
- Поиск по каталогу (индексация через CDC, фасеты, Elasticsearch).
- Сервис загрузки и обработки видео/изображений (очереди, воркеры, CDN).
- Система инвентаризации/остатков (гонки, резервирование, overselling).

## Вопросы с собесов

- [ ] Любой из кейсов 1–6 за 45 минут без подсказок, с цифрами, failure modes и трейдоффами.
- [ ] «Что сломается первым под 10x нагрузкой?» — для каждого своего дизайна.

## Углубление

- Разборы реальных архитектур: как устроены ленты в соцсетях, платёжные системы (Stripe idempotency), очереди уведомлений — инженерные блоги.
- Кейсы на low-level design: спроектировать модуль/классы для парковки, библиотеки, вендинга — иногда спрашивают.
