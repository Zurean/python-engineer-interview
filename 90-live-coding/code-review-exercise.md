# Упражнение: ревью кода с типовыми багами

> **Зачем на собесе:** секция «проведи ревью» всё чаще заменяет live coding, особенно там, где код пишут AI-инструменты (Циан спрашивает прямо). Проверяют: видишь ли баги, расставляешь ли приоритеты, умеешь ли формулировать замечания.

## Минимум для собеса

**Порядок, в котором смотреть PR (и проговаривать):**
1. Корректность и граничные случаи: гонки, ошибки, None, пустые коллекции, таймауты.
2. Безопасность: инъекции, секреты, доступ ([auth-security](../30-backend-design/auth-security.md)).
3. Производительность там, где она важна: N+1, блокировка loop, лишние запросы.
4. Тесты: есть ли, проверяют ли поведение, покрыты ли edge cases.
5. Читаемость и дизайн: имена, размер функций, соответствие слоям.
6. Стиль — последним и желательно автоматикой (ruff).

**Как формулировать:** замечание = проблема + последствие + предложение. Разделять blocking / suggestion / nit. Хвалить хорошее. Не «так не делают», а «здесь при X произойдёт Y, предлагаю Z».

**Типовые баги, которые должны бросаться в глаза:**
- Мутабельный дефолт аргумента → состояние между вызовами.
- Блокирующий вызов (`requests`, `time.sleep`, sync-драйвер БД, тяжёлый CPU) в `async def` → весь сервис встаёт.
- N+1 в цикле по ORM-объектам.
- Голый `except:` / `except Exception: pass` → проглоченные ошибки, в том числе `CancelledError`.
- `@lru_cache` на методе экземпляра или кэш-словарь без ограничения → утечка.
- SQL через f-string → инъекция.
- Отсутствие таймаута у HTTP-вызова; ретраи без backoff/лимита.
- Транзакция, открытая на время внешнего HTTP-вызова; `idle in transaction`.
- Логирование секретов/токенов, PII.
- Создание engine/клиента на каждый запрос; глобальный клиент на уровне импорта без lifespan.
- Неидемпотентный обработчик очереди (at-least-once).
- `datetime.now()` без таймзоны; сравнение float на равенство; `is` для строк/чисел.
- Изменение списка во время итерации; `dict` как упорядоченная структура в коде, рассчитанном на старые версии.
- Тест, который мокает всё и ничего не проверяет; `assert True`.
- Отсутствие индекса под новый `WHERE`; миграция с `ACCESS EXCLUSIVE` на большой таблице.

## Упражнение

Взять (или попросить сгенерировать) фрагмент на 40–60 строк: FastAPI-эндпоинт + сервис + SQLAlchemy-запрос + вызов внешнего API, с 5–7 проблемами из списка выше. Провести ревью вслух за 20 минут, расставить приоритеты. Повторять с разными фрагментами раз в неделю.

## Вопросы с собесов

- [ ] На что смотришь первым при ревью? → *корректность → безопасность → перф → тесты → читаемость*
- [ ] Как даёшь обратную связь, чтобы не обидеть и чтобы исправили? → *проблема + последствие + предложение; приоритеты*
- [ ] Как ревьюишь код, написанный AI? Чем он отличается? → *уверенные, но неверные допущения; выдуманные API; отсутствие edge cases; избыточность*
- [ ] Что делаешь, если PR 2000 строк? → *просить разбить; ревьюить по слоям; договориться о практике маленьких PR*
