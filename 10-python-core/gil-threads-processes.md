# GIL, потоки, процессы

> **Зачем на собесе:** вопрос «что такое GIL» задают почти всегда. Ответ короткий, но нужно уметь продолжить: что он защищает, что нет, когда потоки полезны, что меняет free-threaded Python.

## Минимум для собеса

- **GIL** — мьютекс интерпретатора CPython: в каждый момент байткод выполняет один поток. Нужен, потому что подсчёт ссылок (refcount) не потокобезопасен, и GIL — дешёвый способ его защитить.
- **Что защищает:** внутренние структуры интерпретатора. **Чего не защищает:** твои инварианты. `x += 1` из двух потоков — всё равно гонка (несколько байткод-инструкций), нужен `threading.Lock`.
- **Потоки полезны для I/O:** на блокирующих системных вызовах (сокеты, файлы, `time.sleep`) и в C-расширениях (numpy, hashlib) GIL отпускается → реальный параллелизм ожидания.
- **Потоки бесполезны для CPU-bound** чистого Python: будет даже медленнее из-за переключений (каждые 5 мс, `sys.setswitchinterval`).
- **Процессы** (`multiprocessing`, `ProcessPoolExecutor`): свой интерпретатор и GIL у каждого → CPU-параллелизм. Цена: сериализация через pickle, память, старт.
- **Выбор:** I/O-bound много соединений → asyncio; I/O-bound мало/блокирующие библиотеки → потоки; CPU-bound → процессы (или нативное расширение, numba, Rust).
- **Free-threaded Python (3.13+, PEP 703):** сборка `python3.13t` без GIL. Потоки получают реальный параллелизм, но однопоточный код медленнее, и не все C-расширения совместимы. Пока экспериментальная, в 3.14 — официально поддерживаемая, но не дефолт.
- **Subinterpreters (PEP 684/734):** по GIL на интерпретатор — ещё одна альтернатива.
- **`concurrent.futures`:** единый API для `ThreadPoolExecutor`/`ProcessPoolExecutor`; `submit`, `map`, `as_completed`.

## Вопросы с собесов

- [ ] Что такое GIL, что он защищает и чего не защищает? → *refcount/внутренности; не твои данные*
- [ ] Что меняет free-threaded Python? → *реальный параллелизм потоков, цена — однопоточная скорость и совместимость расширений*
- [ ] Когда потоки в Python полезны, несмотря на GIL? → *I/O, C-расширения отпускают GIL*
- [ ] Потоки vs процессы vs asyncio — как выбирать? → *по типу нагрузки и количеству соединений*
- [ ] Есть ли гонки в Python при наличии GIL? Пример. → *да, x += 1; list.append атомарен, но check-then-act — нет*
- [ ] Как передать данные между процессами? Какие ограничения? → *pickle, Queue, shared_memory; не всё pickl-ится, лямбды*
- [ ] Что такое daemon-поток и чем опасен? → *убивается при выходе без cleanup*

## Углубление

- Как устроена смена владельца GIL: `switch interval`, convoy effect, почему I/O-потоки голодают рядом с CPU-потоками.
- Что именно сделали в PEP 703: biased reference counting, immortal objects, per-object locks, mimalloc.
- `fork` vs `spawn` стартовые методы, почему fork опасен с потоками и asyncio, дефолт на macOS/Linux в 3.14.
- `threading.local`, `contextvars` в потоках.
