# Память и производительность

> **Зачем на собесе:** вопрос «сервис тормозит — твои действия» есть почти на каждом Senior-собесе; X5, Циан и 1440 отдельно требуют оптимизацию. Плюс классический «откуда утечки, если есть GC».

## Минимум для собеса

**Память**
- **Refcount** — основной механизм: объект удаляется, когда счётчик ссылок = 0. **Циклический GC** (`gc`) — дополнительный, для циклов; поколения 0/1/2, запускается по порогам аллокаций.
- **Откуда утечки при GC:** ссылки из глобалов и долгоживущих кэшей; `lru_cache` на методах (держит `self`); незакрытые ресурсы; циклы с `__del__`; накопление в unbounded-очередях/списках; C-расширения.
- **Инструменты:** `tracemalloc` (снапшоты и diff), `objgraph`, `sys.getrefcount`, `gc.get_objects`; в проде — метрика RSS в Prometheus и memory profiler по требованию.
- `__slots__`, генераторы вместо списков, `array`/numpy для числовых массивов — способы снизить память.

**Производительность — алгоритм диагностики**
1. Измерить, не гадать: метрики (p50/p95/p99 latency, RPS, CPU, RSS), трейсы ([[observability]]).
2. Локализовать: где время — в БД, во внешнем API, в CPU, в ожидании lock/loop?
3. Профилировать: `cProfile` + `snakeviz` локально; **`py-spy`** (sampling, можно на живой процесс в проде, `py-spy dump` для «что он сейчас делает»); `scalene`; для async — `py-spy` тоже видит.
4. Типовые находки: N+1 ([[query-optimization-n-plus-1]]), отсутствие индекса, блокирующий вызов в event loop ([[asyncio]]), сериализация больших JSON, логирование в hot path, регулярки, лишние копии.
5. Фикс + повторное измерение. Бенчмарк через `timeit`/`pytest-benchmark`.

**Что ускоряет Python-код**
- Правильные структуры: `set`/`dict` для поиска O(1), `deque` для очереди, `heapq`.
- Встроенные функции и comprehensions вместо циклов; локальные переменные быстрее глобальных.
- Кэширование (`lru_cache`, Redis), батчинг запросов, пулы соединений.
- Для CPU: numpy, процессы, Cython/Rust (PyO3), PyPy. 3.11+ сам быстрее на 10–60 %.

## Вопросы с собесов

- [ ] Сервис медленный. Опиши шаги от симптома до фикса. → *измерить → локализовать → профилировать → фикс → измерить*
- [ ] Откуда в Python утечки памяти, если есть GC? → *глобалы, кэши, lru_cache на методах, циклы с финализаторами*
- [ ] Как работает сборка мусора в CPython? → *refcount + поколенческий GC циклов*
- [ ] Какими инструментами профилировал? В чём разница cProfile и py-spy? → *детерминированный vs sampling; py-spy на проде*
- [ ] p99 латентности вырос, p50 нет. Где искать? → *хвост: GC-паузы, lock contention, медленные запросы под нагрузкой, внешние API*
- [ ] Как измерить, сколько памяти занимает объект? → *sys.getsizeof неполон; tracemalloc; pympler*
- [ ] Что быстрее: `in list` или `in set`? Почему? → *O(n) vs O(1), хеш*

## Углубление

- Аллокаторы: pymalloc, арены, почему RSS не падает после освобождения; `PYTHONMALLOC`.
- Interning, small int cache, free lists.
- Specializing adaptive interpreter (3.11, PEP 659), JIT в 3.13+ — что реально даёт.
- Профилирование async-кода: `yappi`, `asyncio` debug mode, обнаружение slow callbacks.
- Memory arenas в многопроцессной модели gunicorn/uvicorn — почему воркеры «пухнут» и `max_requests`.
