# Генераторы, контекстные менеджеры, декораторы

> **Зачем на собесе:** три самых частых «напиши на доске» задания техскрининга. Нужно уметь написать каждое с закрытыми глазами, включая варианты с параметрами и обработкой исключений.

## Минимум для собеса

**Генераторы**
- `yield` превращает функцию в генератор: ленивый итератор, состояние хранится между вызовами `next()`. Память O(1) вместо O(n).
- Когда генератор, а когда список: генератор — для потоков, больших данных, конвейеров, однократного прохода; список — когда нужны индексы, длина, многократный проход.
- `yield from` — делегирование вложенному итератору/генератору плюс проброс `send()`/`throw()`/возвращаемого значения.
- `send()`, `throw()`, `close()`; `return` в генераторе → `StopIteration.value`.
- Генераторные выражения `(x for x in ...)` vs list comprehension.
- Итератор vs итерируемый: `__iter__` возвращает итератор, у итератора есть `__next__`.

**Контекстные менеджеры**
- Протокол `__enter__`/`__exit__(exc_type, exc, tb)`. Если `__exit__` вернёт `True` — исключение подавлено.
- `contextlib.contextmanager`: код до `yield` = enter, после = exit; исключение из `with` прилетает в точку `yield` → нужен `try/finally`.
- `ExitStack` для динамического набора ресурсов, `asynccontextmanager` для async.
- Применение: транзакции, локи, временные файлы, таймеры, подмена настроек.

**Декораторы**
- Функция, принимающая функцию и возвращающая функцию. `@dec` ≡ `f = dec(f)`.
- `functools.wraps` — сохранить `__name__`, `__doc__`, `__wrapped__`.
- Декоратор с параметрами = фабрика декораторов (три уровня вложенности).
- Декоратор класса, декораторы-классы (`__call__`), стекирование (порядок снизу вверх).
- Для async-функций нужен async-враппер (иначе вернётся непробуждённая корутина).
- Типовые: `lru_cache` (ловушка на методах — держит `self`), `retry`, `timing`, `cached_property`.

## Вопросы с собесов

- [ ] Когда лучше взять генератор, а когда список? Что делает `yield from`? → *память/ленивость; делегирование + проброс send/return*
- [ ] Напиши контекстный менеджер двумя способами. Что происходит с исключением внутри `with`? → *класс и contextmanager; прилетает в __exit__/в yield*
- [ ] Напиши декоратор `retry(times=3, exceptions=(...))` с сохранением метаданных функции.
- [ ] Напиши декоратор, который работает и с sync-, и с async-функциями. → *inspect.iscoroutinefunction*
- [ ] Чем итератор отличается от итерируемого? Можно ли пройти по генератору дважды? → *нет, исчерпывается*
- [ ] Что произойдёт при `return` внутри генератора? → *StopIteration с value*
- [ ] Зачем `functools.wraps`? Что сломается без него? → *имя, доки, интроспекция, pickling*
- [ ] Почему `@lru_cache` на методе экземпляра — утечка? → *кэш держит ссылку на self*
- [ ] Напиши генератор `chunked(iterable, n)` / `flatten(nested)`.
- [ ] Как сделать пайплайн генераторов (читать файл → фильтровать → парсить) без загрузки всего в память?

## Углубление

- Генераторы как корутины до asyncio (PEP 342, 380) — откуда растут ноги async/await.
- `itertools` всерьёз: `chain`, `groupby` (требует сортировки), `islice`, `tee`, `accumulate`, `batched` (3.12).
- `contextlib.suppress`, `closing`, `nullcontext`, `aclosing`.
- Декораторы с состоянием через класс, `ParamSpec` для корректной типизации декораторов ([typing](typing.md)).
- Генераторы и `finally`: когда выполняется cleanup при `close()` / сборке мусора.
